RealtimeKit provides AI-powered transcription and summarization using Cloudflare's AI infrastructure. There are two transcription modes:

| Mode | Provider | Use Case | Output |
|------|----------|----------|--------|
| **Real-time** | [Deepgram Nova-3](/workers-ai/models/deepgram-nova-3/) | Live captions during meeting | Streaming transcripts |
| **Post-meeting** | [Whisper Large v3 Turbo](/workers-ai/models/whisper-large-v3-turbo/) | Offline processing after meeting | SRT, VTT, CSV, JSON files |

## Real-time transcription

Real-time transcription uses [Deepgram Nova-3](/workers-ai/models/deepgram-nova-3/) via Cloudflare AI Gateway to provide low-latency speech-to-text during live meetings.

### Enable via preset

Set `transcription_enabled: true` in the participant's [preset](/realtime/realtimekit/concepts/preset/). Only participants with this flag will have their audio transcribed.

### Configure transcription

Pass `ai_config.transcription` when [creating a meeting](/realtime/realtimekit/concepts/meeting/):

```json
{
  "title": "Team Standup",
  "ai_config": {
    "transcription": {
      "language": "en-US",
      "keywords": ["RealtimeKit", "Cloudflare", "WebRTC"],
      "profanity_filter": false
    }
  }
}
```

#### Configuration options

| Option | Type | Description |
|--------|------|-------------|
| `language` | string | Transcription language code. Default: `en-US` |
| `keywords` | string[] | Terms to boost recognition accuracy (names, jargon) |
| `profanity_filter` | boolean | Filter offensive language. Default: `false` |

### Consume real-time transcripts

#### Client SDK

```javascript
// Access all transcripts
const transcripts = meeting.ai.transcripts;

// Listen for new transcripts
meeting.ai.on("transcript", (data) => {
  console.log(`${data.name}: ${data.transcript}`);
  console.log(`Partial: ${data.isPartialTranscript}`);
});
```

Transcript event payload:

```json
{
  "id": "1a2b3c4d-5678-90ab-cdef-1234567890ab",
  "name": "Alice",
  "peerId": "4f5g6h7i-8j9k-0lmn-opqr-1234567890st",
  "userId": "uvwxyz-1234-5678-90ab-cdefghijklmn",
  "customParticipantId": "abc123xyz",
  "transcript": "Hello everyone",
  "isPartialTranscript": false,
  "date": "2024-08-07T10:15:30.000Z"
}
```

| Field | Description |
|-------|-------------|
| `isPartialTranscript` | `true` = interim result (speaker still talking), `false` = final result |
| `peerId` | Unique per connection (changes if participant rejoins) |
| `userId` | Persistent participant identifier |
| `customParticipantId` | Your custom identifier from Add Participant API |

## Post-meeting transcription

Post-meeting transcription uses [Whisper Large v3 Turbo](/workers-ai/models/whisper-large-v3-turbo/) via Workers AI. It processes recorded audio after the meeting ends and generates transcript files in multiple formats.

### How it works

1. During the meeting, audio is recorded per participant
2. When the meeting ends, recordings are downloaded from storage
3. Each participant's audio is transcribed using Whisper
4. Transcripts are consolidated into a unified timeline
5. Output files are uploaded to R2 storage
6. Webhook is sent with download URLs

### Supported languages (Post-meeting)

Post-meeting transcription supports all ISO 639-1 language codes via Whisper:

:::caution[Language code mapping]
Whisper does not support `en-US`, `en-IN`, or `multi` codes. These are automatically mapped to `en` for post-meeting transcription.
:::

All languages from the [full language list](#supported-languages-real-time) are supported except:
- `en-US` → mapped to `en`
- `en-IN` → mapped to `en`  
- `multi` → mapped to `en`

### Output formats

Post-meeting transcripts are available in four formats:

| Format | Content-Type | Use Case |
|--------|--------------|----------|
| **CSV** | `text/csv` | Spreadsheet analysis, data processing |
| **SRT** | `application/x-subrip` | Video subtitle overlay |
| **VTT** | `text/vtt` | Web video captions (HTML5 `<track>`) |
| **JSON** | `application/json` | Programmatic access, custom UIs |

#### CSV format

```csv
Timestamp,Participant ID,User ID,Custom Participant ID,Participant Name,Transcript
2024-08-07T10:15:30.000Z,peer-123,user-456,cust-789,Alice,Hello everyone
2024-08-07T10:15:35.000Z,peer-234,user-567,cust-890,Bob,Hi Alice
```

#### JSON format

```json
[
  {
    "startTime": 0,
    "endTime": 2.5,
    "sentence": "Hello everyone",
    "peerData": {
      "id": "peer-123",
      "userId": "user-456",
      "displayName": "Alice",
      "cpi": "cust-789"
    }
  }
]
```

### Fetch transcripts

#### Via webhook

Configure a webhook with `meeting.transcript` event:

```json
{
  "event": "meeting.transcript",
  "meetingId": "meeting-123",
  "sessionId": "session-456",
  "transcriptDownloadUrl": "https://...",
  "transcriptDownloadUrlExpiry": "2024-08-14T10:15:30.000Z"
}
```

#### Via REST API

Fetch transcript for a session (available for 7 days):

```bash
curl -X GET "https://api.realtime.cloudflare.com/v2/sessions/{sessionId}/transcript" \
  -H "Authorization: Basic {credentials}"
```

Response:

```json
{
  "sessionId": "session-456",
  "transcriptDownloadUrl": "https://...",
  "transcriptDownloadUrlExpiry": "2024-08-14T10:15:30.000Z"
}
```

## Meeting summary

Summarization uses [Llama 3.2 3B Instruct](/workers-ai/models/llama-3.2-3b-instruct/) to generate meeting summaries from transcript data.

:::note
Transcription must be enabled to use summarization.
:::

### Enable summarization

Set `summarize_on_end: true` when creating a meeting:

```json
{
  "title": "Product Review",
  "ai_config": {
    "transcription": {
      "language": "en-US"
    },
    "summarization": {
      "word_limit": 500,
      "text_format": "markdown",
      "summary_type": "team_meeting"
    }
  },
  "summarize_on_end": true
}
```

### Configuration options

| Option | Type | Values | Description |
|--------|------|--------|-------------|
| `word_limit` | number | 150-1000 | Maximum words in summary |
| `text_format` | string | `plain_text`, `markdown` | Output format |
| `summary_type` | string | See below | Meeting context for better summaries |

#### Summary types

| Type | Best for |
|------|----------|
| `general` | Default, any meeting |
| `team_meeting` | Regular team syncs |
| `sales_call` | Customer sales conversations |
| `client_check_in` | Client status updates |
| `interview` | Job interviews |
| `daily_standup` | Agile standups |
| `one_on_one_meeting` | 1:1 meetings |
| `lecture` | Educational content |
| `code_review` | Technical code reviews |

### Consume summaries

#### Via webhook

Configure `meeting.summary` event:

```json
{
  "event": "meeting.summary",
  "meetingId": "meeting-123",
  "sessionId": "session-456",
  "summaryDownloadUrl": "https://...",
  "summaryDownloadUrlExpiry": "2024-08-14T10:15:30.000Z"
}
```

#### Via REST API

```bash
# Get summary
curl -X GET "https://api.realtime.cloudflare.com/v2/sessions/{sessionId}/summary" \
  -H "Authorization: Basic {credentials}"

# Trigger summary manually (if not auto-generated)
curl -X POST "https://api.realtime.cloudflare.com/v2/sessions/{sessionId}/summary" \
  -H "Authorization: Basic {credentials}"
```

## Complete example

Create a meeting with full AI configuration:

```json
{
  "title": "Weekly Engineering Sync",
  "ai_config": {
    "transcription": {
      "language": "en-US",
      "keywords": ["Kubernetes", "deployment", "CI/CD"],
      "profanity_filter": false
    },
    "summarization": {
      "word_limit": 300,
      "text_format": "markdown",
      "summary_type": "team_meeting"
    }
  },
  "summarize_on_end": true
}
```

Handle transcripts in your client:

```javascript
// Real-time display
meeting.ai.on("transcript", (data) => {
  if (data.isPartialTranscript) {
    updatePartialCaption(data.peerId, data.transcript);
  } else {
    finalizeCaption(data.peerId, data.transcript);
  }
});

// Store for later
const allTranscripts = [];
meeting.ai.on("transcript", (data) => {
  if (!data.isPartialTranscript) {
    allTranscripts.push(data);
  }
});
```

## Storage and retention

- Transcripts and summaries are stored for **7 days** from meeting start
- Files are stored in R2 with presigned URLs for secure access
- Download URLs expire after 7 days
